지금 장면이 async · await에서는 어디일까요?
async
기다리는 동안 다른 일을 할 수 있는 함수로 선언합니다. 이것만 붙인다고 다른 일이 저절로 시작되지는 않습니다.
await
이 함수는 결과가 올 때까지 잠깐 기다려요라는 뜻입니다. 그동안 실행할 다른 일이 준비돼 있으면 처리할 수 있습니다.
웹에서는 프린터 대신 서버 응답·파일 읽기·외부 API 응답을 기다리는 상황에 적용할 수 있습니다. CPU 계산 자체를 빠르게 해주는 기능은 아닙니다.

Uvicorn 실행과 어떤 관계인가요?
실행명령 나눠보기
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
부분실제로 가리키는 것
python -m uvicorn현재 Python 환경에 설치된 Uvicorn을 실행합니다.
main현재 폴더의 main.py 모듈입니다. 파일이 api.py라면 api:app으로 바꿉니다.
appmain.py의 app = FastAPI()로 만든 객체입니다.
--host 127.0.0.1내 컴퓨터에서 접속할 주소입니다.
--port 8000서버가 기다릴 포트입니다. 8001로 바꾸면 접속 주소도 :8001로 맞춥니다.
--reload개발 중 Python 파일을 수정하면 서버를 다시 불러옵니다.
패키지 설치는 실행 준비이고, Uvicorn 명령 실행은 서버 시작입니다.
이 예제에서 python main.py만 실행하면 app 객체를 만들고 끝나므로 웹 서버가 열리지 않습니다.
ASGI는 Uvicorn이 FastAPI 앱을 호출하고 응답을 받는 연결 규칙입니다.
host·port는 서버가 요청을 받을 위치를 정합니다.
async·await는 앱 함수에서 대기 중 다른 작업을 진행할 수 있도록 구성하는 코드입니다.

Uvicorn은 HTTP 요청을 받아 Python 앱에 전달하는 서버이고, FastAPI는 경로에 맞는 함수와 입력 검사를 연결하는 앱입니다.

먼저 무슨 일이 있었나요?
예시 상황 · 10:05 운영 담당자가 서비스 화면에서 DB 연결 실패를 확인했습니다. 상태 확인도 3회 연속 실패했고, 로그에는 connection refused가 남았습니다. 아직 DB 프로세스 중단인지, 접속 주소·포트 문제인지, 네트워크 문제인지는 모릅니다.
사용자 입력 /incident_analysis system_name=db symptom=down
호스트 앱이 받은 요청 DB 장애를 조사하고 운영 매뉴얼에 따른 대응 절차와 현재 상태를 정리해 주세요.
사용자
장애 증상을 보고 조사 명령을 입력한 운영 담당자입니다.
호스트 앱
사용자 화면과 백엔드를 포함한 애플리케이션입니다. 명령을 읽고 MCP 서버·LLM을 호출하며 결과를 화면에 표시합니다.
MCP 서버
등록된 절차 템플릿·운영 문서·조회 함수를 제공합니다. 이 서버가 스스로 조사 계획을 정하지는 않습니다.
LLM
전달받은 질문·절차·문서를 보고 현재 상태 조회를 요청하고, 돌아온 결과로 답변을 작성합니다.
